# Выписки, рецензия, синтез и предложения: формат и правила (схема v2)

Главное правило: **неподтверждённого содержания нет**. Тезис — короткая подпись к выписке, а не вывод модели. За каждым тезисом стоит дословная цитата и место в файле. Синтез и предложения допустимы, но опираются только на допущенные тезисы и помечены как слой B и слой C.

## Три проверки тезиса

| Проверка | Кто | Статусы | Что значит |
|---|---|---|---|
| Точность цитаты | `check_claims.py` | верно / ошибка | цитата стоит в файле, с начала слова на указанной строке; источник из `index.json`, файл не изменён |
| Смысловая поддержка | рецензент | `supported`, `partially_supported`, `unsupported`, `not_reviewed` | говорит ли цитата то, что написано в подписи |
| Границы применимости | рецензент | `within_scope`, `overgeneralized`, `unclear`, `not_reviewed` | не расширена ли подпись за пределы выборки, страны, методики, условий |

**Допуск в основной слой (A):** цитаты верны **и** рецензия свежая **и** `supported` **и** `within_scope`. Один общий процент уверенности не используется.

Рецензия хранит хеш тезиса: подпись, вид, выписки, `cited_from`, `scope`, `comparison`. Изменил что-то из этого — рецензия **устарела**, тезис снова не допущен до новой рецензии. Старый проект без рецензий открывается, но ни один тезис в нём не допущен.

Совпадение цитаты не означает, что утверждение автора истинно. Рецензент-модель может ошибаться.

Хеш защищает от **случайного** устаревания: подпись поправили — допуск снят. От намеренной подделки он не защищает: секрета нет, хеш может посчитать любой, кто пишет `reviews.json` или `claims.json`. Поэтому правило: рецензию пишет только `review.py --apply`, а её `hash` берётся только из пакета, который видел рецензент.

## Формат `claims.json`

```json
{
  "schema_version": 2,
  "question": "профессиональное выгорание учителей: какие методики измерения сравнивают",
  "sections": [
    {
      "title": "Структура MBI на учителях",
      "claims": [
        {
          "id": "c21",
          "kind": "fact",
          "thesis": "Бирн (учителя трёх ступеней; 1159, 388 и 1384 человек): анализ поддержал трёхфакторную структуру MBI.",
          "scope": {"sample": "учителя начальной, средней и старшей школы", "country": "Канада",
                    "language": null, "instrument": "MBI", "design": "КФА", "outcomes": null},
          "evidence": [
            {"source": "Byrne1993_W2085494637", "line": 14, "quote": "дословный текст из файла"}
          ],
          "review": {"support": "supported", "scope": "within_scope", "mode": "independent",
                     "date": "2026-10-24", "note": "…", "problems": [], "fix": "", "hash": "…"}
        }
      ]
    }
  ],
  "synthesis": [],
  "proposals": []
}
```

Поле `review` пишет только `review.py --apply`. Руками его не заполнять. Хеш берётся из пакета рецензента: `--apply` откажет, если тезис изменился после `--packet`. Старый проект (без `schema_version`) не допускает ни одного тезиса; первая рецензия через `--apply` переводит его на v2, и тогда проверяется вся структура v2.

### Поля тезиса
- `id` — уникален во всём файле: `c1`, `c2`…
- `kind`:
  - `fact` — результат или данные: выборка, коэффициент, число;
  - `opinion` — оценка или интерпретация автора;
  - `definition` — определение понятия;
  - `method` — описание методики или процедуры;
  - `contradiction` — расхождение источников. Нужны выписки **минимум из двух разных источников** и карточка `comparison`.
- `evidence[].source` — имя файла в `sources/` без `.md`.
- `evidence[].line` — номер строки, **на которой начинается** цитата.
- `evidence[].quote` — текст как в файле. Перенос строки внутри цитаты допустим. Можно убрать перенос слова по слогам («выго-рание» → «выгорание»). Остальное — без правок. Пропуск внутри цитаты не допускается: два куска — две выписки.
- `scope` (необязательно) — границы исследования: `sample`, `country`, `language`, `instrument` (версия методики), `design`, `outcomes`. Неизвестно — `null`; страница покажет «неизвестно». Не достраивать из общих знаний.
- `cited_from` (обязательно, если источник пересказывает чужую позицию или результат) — `{"original": "Kristensen et al., 2005", "note": "первоисточник не прочитан"}`. Подпись тогда — «Шоман и соавт. приводят мнение Кристенсена…», а не «Кристенсен считает…».
- `status: "excluded"` и `exclusion` — только через `review.py --exclude`.

### Карточка противоречия `comparison`
```json
"comparison": {
  "question": "какая шкала лучше подходит для измерения выгорания",
  "same": ["оценка психометрики MBI и CBI"],
  "different": ["учителя Греции против методик для специалистов в области психического здоровья", "КФА против COSMIN"],
  "type": "different_conditions",
  "open": "сравнения на одной выборке учителей не найдено"
}
```
`type`:
- `direct` — прямое противоречие: тот же вопрос, сопоставимые выборка, методика и показатель, выводы расходятся;
- `different_conditions` — результаты различаются при разных условиях или выборках;
- `different_definitions` — авторы по-разному определяют понятие;
- `insufficient_data` — данных для сопоставления мало.

Перед записью проверь сопоставимость: вопрос, определение понятия, выборка, условия, методика, показатель, срок. «Значимо» в одной работе и «не значимо» в другой — само по себе не противоречие.

## Правила подписи (`thesis`)
1. Подпись повторяет то, что авторы изучали и писали: та же выборка, те же переменные и термины.
2. Модальность — как у автора: «suggest» — «результаты указывают», а не «доказано».
3. Без обобщений за пределы выборки и без причинного языка, если у автора его нет.
4. Подпись не добавляет фактов, которых нет в выписках. Сведения о выборке — отдельной выпиской.
5. Чьё мнение — видно из подписи: «По Маслач…», «Водопьянова считает…».
6. Отрицания и условия сохранять. Гипотезу и намерение не выдавать за результат.
7. Для аннотации не достраивать методы и ограничения.

## Цитата
- Длина — до 60 слов. Длиннее — выбрать ключевую часть.
- Цитата из файла со статусом «только аннотация» допустима. На странице она помечается.
- Числа (выборки, коэффициенты, α) брать только из выписки.

## Синтез (слой B)
```json
"synthesis": [{"id": "s1", "text": "…", "basis": ["c10", "c12", "c25"], "limits": "две работы, разные выборки"}]
```
- Опора — только допущенные тезисы `c…`. Синтез на другом синтезе запрещён: так нет циклов обоснования.
- Не добавляет фактов. «Большинство исследований» — только с подсчётом по `basis`.
- `limits` обязательно.

## Предложения ИИ (слой C)
```json
"proposals": [{"id": "p1", "text": "…", "basis": ["s1", "c23"], "assumptions": ["…"],
               "not_checked": "что не проверялось", "pilot": "как проверить на месте",
               "risks": "риски и когда остановиться (необязательно)"}]
```
- Опора — допущенные тезисы или верный синтез.
- Это предложение модели. Не выдавать его за рекомендацию авторов статей.
- Обязательны `assumptions` (непустой список), `not_checked` и `pilot`.

## Порядок работы
1. Прочитать файл источника целиком или нужные разделы (Read с номерами строк).
2. Выписать цитату **копированием**, номер строки взять из вывода Read.
3. `check_claims.py` — исправлять по подсказке скрипта; не больше 3 кругов, затем `review.py --exclude`.
4. `review.py --packet` → рецензия сабагентом → `review.py --apply … --mode independent`.
5. Недопущенный тезис на страницу в основной слой и в аудио не попадает; виден в блоке «Не допущены» с причиной.
